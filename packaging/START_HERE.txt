NEW IN V0.2B // ETHERCOMPOSER V0.1
---------------------------------
CREATE no longer sends raw free-form text straight to the renderer.
Every generation now passes through EtherComposer first.

EtherComposer translates production language into a structured musical blueprint containing:
- BPM and key lineage
- energy
- drum density
- bass weight
- transient density
- vocal / negative space
- texture grit
- arrangement sections and bar counts

Example intent:
  haunted cloud-rap instrumental, enormous negative space,
  submerged bass, beautifully degraded

becomes a renderer-facing plan with sparse drums, larger vocal space,
stronger low-end weighting, degraded texture and explicit song sections.

The planner is deterministic and renderer-agnostic. ACE-Step receives the blueprint today;
future JASCO / SongGeneration / other renderer providers can consume the same Composer layer
without changing the EtherBeat UI or user workflow.

CURRENT LIMITS
--------------
- EtherComposer V0.1 is rule-based and inspectable; a learned planner can replace/augment it later.
- Text-to-instrumental remains the active generation path.
- Reference-conditioned generation / Extend / Variation still need dedicated control mappings.
- Detailed byte-level model-download progress is not yet exposed in the UI.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public test package.
