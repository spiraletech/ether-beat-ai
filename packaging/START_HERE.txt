ETHERBEAT // ALIEN WORKSHOP V0.2D

UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

  home | create | library | now playing | song lab | engine

NEW IN V0.2D // PROVIDER ROUTER V0.1
-----------------------------------
EtherBeat no longer assumes one model backend equals the entire music engine.

Generation requests now carry a renderer intent:

  AUTO | DRAFT | QUALITY | CONTROL | VOCAL

Every registered provider advertises explicit capabilities, including:
- text-to-instrumental
- variation
- extend
- audio-to-audio
- reference audio support
- Draft role
- Quality role
- Control role
- Vocal role
- local-runtime status

ROUTING RULES
-------------
AUTO text-to-instrumental jobs resolve to QUALITY.
Variation / Extend / Audio-to-Audio jobs resolve to CONTROL.
Explicit DRAFT / QUALITY / CONTROL / VOCAL intent is respected.

EtherBeat selects only a provider that supports both the generation mode and requested role.
Reference requests also require explicit reference-audio capability.

If no provider supports the job, EtherBeat now fails clearly instead of silently sending the request to an incompatible model.

CURRENT LIVE PROVIDER
---------------------
ACE-Step remains the current local text-to-instrumental renderer and therefore covers the present Draft/Quality path.

No fake Control or Vocal provider is registered yet. Those jobs remain intentionally unavailable until dedicated provider mappings are implemented.

ENGINE STACK
------------
  ETHERBEAT UI
      -> EtherDNA V0.1
      -> EtherComposer V0.1
      -> Provider Router V0.1
          -> Draft provider
          -> Quality provider
          -> Control provider
          -> Vocal provider
      -> selected renderer
      -> generated audio
      -> library / now playing / analyzer

The registry is provider-name agnostic. Future ACE variants, JASCO-style control engines, SongGeneration-class vocal renderers, or EtherTech-native models can be registered without replacing Composer, EtherDNA or the EtherBeat UI shell.

TESTED ROUTING CONTRACT
-----------------------
Automated tests verify:
- AUTO text generation chooses a Quality provider.
- Explicit Draft chooses a Draft provider.
- Variation requires a reference-capable Control provider.
- Unsupported Vocal work is rejected instead of falling back incorrectly.
- Existing single-provider generation remains compatible.

LOCAL DATA
----------

CURRENT LIMITS
--------------
- ACE-Step is still the only live model provider bundled into the current Windows path.
- Dedicated Control and Vocal providers are not wired yet.
- EtherDNA learned embeddings are a later layer; V0.1 remains DSP-derived.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public test package.
