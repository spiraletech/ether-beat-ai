NEW IN V0.2Q // ETHERARRANGEMENT V0.1
-------------------------------------
Every analyzed track can now receive a persistent arrangement plan beside the source audio:

  <audio>.etherarrangement.json

The plan is an ordered graph of arrangement slots. Each slot records:
- stable slot ID
- section kind and label
- provenance: source / duplicate / placeholder
- source section start/end when reusable audio exists
- origin slot ID for duplicates
- generation instruction for placeholders

PROVENANCE MODEL
----------------
EtherArrangement distinguishes three meanings:

SOURCE
  Reuse an existing detected section from the current audio.

DUPLICATE
  Repeat/reuse a previous arrangement slot. The duplicate retains source timing and points back to the slot it came from.

PLACEHOLDER
  A structural section exists in the plan but has no audio yet. A later renderer can synthesize material for that slot.

This distinction is intentionally renderer-neutral. V0.2Q does not pretend ACE can physically splice and reorder complete audio yet.

VISIBLE ARRANGEMENT RAIL
------------------------
NOW PLAYING adds a compact arrangement rail above EtherSections:

  INTRO > VERSE > HOOK > BRIDGE > OUTRO

with:

  < SLOT | SLOT > | DUP | < MOVE | MOVE > | + ALT | DELETE

< SLOT / SLOT >
  Select arrangement slots. Selecting a source-backed slot also moves the existing timeline repaint window to that source section.

DUP
  Inserts a duplicate immediately after the selected slot while preserving its source provenance.

< MOVE / MOVE >
  Reorders the selected slot in the arrangement plan.

+ ALT
  Inserts a generated placeholder of the selected section kind after it, for example HOOK ALT. The placeholder intentionally has no source timestamps yet.

DELETE
  Removes the selected slot from the arrangement plan only. The underlying source WAV and EtherVersions graph are unchanged. EtherArrangement refuses to remove the final remaining slot.

REVISION MODEL
--------------
Every structural mutation increments an arrangement revision counter.

Example:

  rev 0: INTRO > VERSE > HOOK > BRIDGE > OUTRO
  DUP HOOK
  rev 1: INTRO > VERSE > HOOK > HOOK* > BRIDGE > OUTRO
  + ALT
  rev 2: INTRO > VERSE > HOOK > HOOK ALT+ > HOOK* > BRIDGE > OUTRO
  MOVE >
  rev 3: ...

* indicates a duplicate in the compact UI sequence.
+ indicates a not-yet-rendered placeholder.

RENDERER-NEUTRAL BLUEPRINT
--------------------------
EtherArrangement can compile the current graph into a textual arrangement blueprint with slot order, provenance, source timing, duplicate origins and placeholder instructions.

The blueprint is infrastructure for a future arrangement renderer / Composer pass. V0.2Q persists and edits the graph but does NOT physically assemble a new waveform from the graph yet.

PERSISTENCE
-----------
A tracked song can now accumulate:

  song.wav
  song.wav.etherdna.json
  song.wav.etherversion.json
  song.wav.ethersections.json
  song.wav.etherarrangement.json

Loading the song later restores its arrangement revision rather than rebuilding the plan from scratch.

CURRENT LIMITS
--------------
- EtherArrangement V0.1 edits a persistent structure graph; it does not physically concatenate/splice/re-render the graph into a finished waveform yet.
- Placeholder slots represent material that still needs a future renderer/generation stage.
- V0.1 section naming still uses a structural prior + energy-transition heuristic, not a trained semantic structure model.
- Repeated/custom section detection is represented cleanly in EtherArrangement, but EtherSections detection itself still starts from one INTRO / VERSE / HOOK / BRIDGE / OUTRO pass.
- EtherTimeline remains a 128-bin time-energy envelope rather than sample-resolution waveform peaks.
- Playback/seek still uses MCI millisecond positioning.
- Extend remains intentionally blocked until continuation behavior is separately validated.
- SEARCH x4 is sequential until provider-native batching or a dedicated fast Draft engine is wired.
- EtherCritic remains DSP-derived; learned semantic/taste heads come later.
- Pleiadian taste adaptation is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public package.
