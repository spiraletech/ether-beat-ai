NEW IN V0.2E // ETHERDRAFT V0.1
------------------------------
EtherBeat now has a multi-candidate draft layer above the provider router.

One source request can produce a reproducible batch of musical candidates instead of treating generation as one irreversible answer.

ETHERDRAFT CONTRACT
-------------------
Default batch size: 4 candidates.
Supported range: 1-8 candidates.

Each candidate receives:
- batch index
- deterministic derived seed
- Draft renderer intent
- selected provider lineage
- generated audio artifact
- generation metadata artifact
- independent success/error state

Candidate 0 preserves the resolved base seed. Later candidates derive stable, distinct seeds from that base seed.

A fixed source seed therefore recreates the same candidate seed search-space across runs.

BATCH MANIFEST
--------------
EtherDraft writes a persistent manifest:

  draft-<base-seed>-<timestamp>.etherdraft.json

The manifest records:
- schema etherbeat.draft.v1
- batch ID
- base seed
- source prompt
- candidate count
- success count
- per-candidate seed
- provider
- audio/metadata paths
- per-candidate error state

One failed candidate does not erase successful siblings. V0.1 can continue the batch after an individual failure.

ENGINE STACK
------------
  ETHERBEAT UI
      -> EtherDNA V0.1
      -> EtherComposer V0.1
      -> EtherDraft V0.1
          -> Provider Router V0.1
              -> Draft provider
              -> Quality provider
              -> Control provider
              -> Vocal provider
          -> candidate A
          -> candidate B
          -> candidate C
          -> candidate D
      -> future EtherCritic ranking
      -> selected candidate / Quality render

CURRENT LIVE PROVIDER
---------------------
ACE-Step remains the current local text-to-instrumental renderer and advertises Draft + Quality capability.
The EtherDraft layer is provider-agnostic, so a faster dedicated Draft provider can replace it later without changing the batch contract or EtherBeat UI.

TESTED ETHERDRAFT CONTRACT
--------------------------
Automated tests verify:
- four requested candidates produce four successful artifacts
- all candidate seeds are distinct
- candidate 0 preserves the supplied base seed
- every candidate is routed with Draft intent
- the batch manifest is created
- manifest prompt and success lineage are preserved
- Windows/MSVC and Ubuntu/GCC both pass the same test suite

UI NOTE
-------
V0.2E establishes and validates the Draft engine substrate first.
The existing CREATE button remains the direct Quality-generation path in this package.
Draft candidate selection will become useful in the UI when the next ranking/critic layer can score and compare the batch rather than dumping four unranked files onto the user.

CURRENT LIMITS
