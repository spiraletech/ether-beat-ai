ETHERBEAT // ALIEN WORKSHOP V0.2M

UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

  home | create | library | now playing | song lab | engine

V0.2M evolves NOW PLAYING instead of redesigning the product shell. The persistent EtherVersions graph introduced in V0.2L is now visible and driveable as a producer/version workspace.

NEW IN V0.2M // ETHERVERSIONS WORKSPACE V0.1
-------------------------------------------
NOW PLAYING keeps its split analyzer + EtherControl workspace and adds an EtherVersions rail directly beneath it.

Visible version actions:
- PARENT
- < CHILD
- CHILD >
- HEAD
- PROMOTE

The rail also shows whether the current audio is the promoted HEAD or an unpromoted branch, its operation type, root identity prefix, and branch/child count.

PARENT
------
PARENT walks from the current control version to its immediate parent without deleting anything.

Example:

  ORIGINAL
     -> VARIATION A
          -> REPAINT A1   [current]

PARENT loads VARIATION A.
Another PARENT loads ORIGINAL.
At the root, PARENT is a no-op with an explicit status message.

CHILD / SIBLING A-B NAVIGATION
------------------------------
At a root node, CHILD arrows enter the root's direct child branches.

When the current node already has a parent, CHILD arrows operate across that common parent's direct children. This means sibling variations can be A/B-switched without returning to the parent between every listen.

Example:

  ORIGINAL
     -> VARIATION A
     -> VARIATION B
     -> VARIATION C

While listening to VARIATION B:

  < CHILD  -> VARIATION A
  CHILD >  -> VARIATION C

Branch ordering is deterministic: children are sorted by creation timestamp with version ID as a stable tie break, rather than relying on filesystem enumeration order.

HEAD
----
HEAD jumps from any node in a root lineage to the version currently promoted for that lineage.

If the current node already is HEAD, EtherBeat reports that directly instead of reloading it.

PROMOTE
-------
PROMOTE moves the lineage HEAD to the currently loaded version.
No source, sibling, child or ancestor audio is deleted.

This makes approval explicit:

  generate/edit freely
      -> compare branches
      -> choose the version you actually want
      -> PROMOTE

A future render/edit can still branch from any older node afterward.

AUTOMATIC LINEAGE
-----------------
Version registration remains in ModelRouter rather than only in Win32 button code.

Any successful source-conditioned EtherControl render automatically registers:
- source/root lineage when needed
- child version
- operation type
- parent relationship
- producer instruction

The Now Playing workspace simply queries and drives that persistent graph.

TRACK LOADING
-------------
Loading a generated/local Library track into NOW PLAYING now initializes EtherVersions root metadata automatically when the track has no prior lineage.

Tracked control children retain their existing parent/root metadata; they are not mistakenly re-rooted when loaded later.

CURRENT PRODUCER FLOW
---------------------
CREATE:
  EtherComposer
      -> EtherSearch x4
      -> EtherDNA
      -> EtherCritic
      -> EtherPromote
      -> NOW PLAYING / EtherVersions root

CONTROL:
  NOW PLAYING
      -> Variation / Replace Section
      -> ModelRouter
      -> ACE cover / repaint
      -> new local child audio
      -> EtherVersions automatic registration
      -> NOW PLAYING branch

VERSION WORKSPACE:
  current branch
      -> PARENT / CHILD A-B / HEAD
      -> compare
      -> PROMOTE selected version

ORIGINAL PRESERVATION
---------------------
EtherVersions never implements destructive undo.
Version navigation changes which audio node is loaded; promotion changes only the HEAD metadata record.
All audio branches remain local until the user deliberately removes files outside this workflow.

CURRENT LIMITS
--------------
- The V0.2M rail navigates parent, sibling/direct-child branches and HEAD; a full graphical tree/timeline view is later.
- Compare is fast branch switching, not simultaneous dual-waveform synchronized A/B playback yet.
- Extend remains intentionally blocked until continuation behavior is separately validated.
- ACE does not claim true component locks or isolated drum/melody/chord conditioning through this adapter.
- SEARCH x4 is sequential until provider-native batching or a dedicated fast Draft engine is wired.
- EtherCritic remains DSP-derived; learned semantic/taste heads come later.
- Pleiadian taste adaptation is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public package.
