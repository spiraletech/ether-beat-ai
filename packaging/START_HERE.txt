ETHERBEAT // ALIEN WORKSHOP V0.2S

UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

  home | create | library | now playing | song lab | engine

V0.2S evolves V0.2R's physical EtherAssemble path rather than redesigning the shell. Search, EtherControl, EtherVersions, EtherCompare, EtherTimeline, EtherSections, EtherArrangement and EtherAssemble remain intact; EtherSeam adds measurable boundary quality analysis and adaptive section joins.

NEW IN V0.2S // ETHERSEAM V0.1
------------------------------
Before EtherAssemble joins two normalized PCM sections, EtherSeam analyzes the outgoing tail and incoming head.

A seam score is reported from 0.0 to 1.0:

  0.0 = low discontinuity / nearly continuous boundary
  1.0 = high discontinuity risk

This score is NOT a music-quality rating. It answers only: how abrupt is this particular audio join likely to be?

MEASURED HEADS
--------------
EtherSeam V0.1 combines five deterministic DSP heads:

RMS JUMP
  Difference in boundary-window loudness.

SPECTRAL JUMP
  Difference between normalized 8-point Goertzel spectral signatures across the boundary.

DC JUMP
  Difference in short-window mean sample value / offset.

TRANSIENT COLLISION
  Difference and overlap in boundary derivative/transient activity.

SAMPLE JUMP
  Instantaneous last-sample -> first-sample discontinuity proxy.

Default weighting:

  RMS                 22%
  spectral            30%
  DC                  14%
  transient collision 20%
  sample jump         14%

ADAPTIVE CROSSFADE
------------------
V0.2R used one fixed 20 ms crossfade for every join.

V0.2S chooses a fade separately for each measured boundary:

  clean seam  -> near 5 ms
  rough seam  -> progressively longer
  high-risk   -> up to 100 ms

The mapping is bounded and deterministic. EtherAssemble still supports the old fixed-crossfade mode for testing/comparison, and the core can accept up to 250 ms if a later producer UI exposes manual seam tuning.

SEVERE SEAMS
------------
The default severe-risk threshold is:

  seam_score >= 0.82

V0.2S records and surfaces severe seams but does not automatically destroy/reject the assembly. The core includes an optional reject_severe_seams mode for future strict rendering workflows.

  <audio>.etherassemble.json

The first arrangement slot has no incoming boundary, so its seam fields remain zero/unmeasured.

CURRENT LIMITS
--------------
- EtherSeam V0.1 uses compact deterministic DSP proxies rather than a learned perceptual transition model.
- Goertzel spectral comparison uses eight frequency anchors, not a future full perceptual embedding.
- Adaptive fades smooth discontinuities but cannot repair a musically incompatible independently generated +ALT section.
- Context-conditioned in-between generation / neighboring-waveform continuation remains a later renderer step.
- Sample-rate conversion remains linear V0.1 resampling rather than a high-order production resampler.
- EtherSections still begins from an energy-transition heuristic rather than a learned semantic section classifier.
- EtherTimeline remains a 128-bin time-energy envelope rather than sample-resolution waveform peaks.
- Playback/seek still uses MCI millisecond positioning.
- Extend remains intentionally blocked until continuation behavior is separately validated.
- SEARCH x4 is sequential until provider-native batching or a dedicated fast Draft engine is wired.
- EtherCritic remains DSP-derived; learned semantic/taste heads come later.
- Pleiadian taste adaptation is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public package.
