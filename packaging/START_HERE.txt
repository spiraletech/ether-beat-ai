  home | create | library | now playing | song lab | engine

NEW IN V0.2P // ETHERSECTIONS V0.1
----------------------------------
Every analyzed track can now receive a persistent five-region structural map:

  INTRO | VERSE | HOOK | BRIDGE | OUTRO

The map stores start/end time and confidence for each region and persists beside the source audio as:

  <audio>.ethersections.json

DETECTION MODEL
---------------
V0.1 is deterministic and intentionally inspectable. It is not a learned verse/hook classifier.

EtherSections starts from a five-part structural prior, then uses the real 128-bin EtherTimeline energy envelope to search near expected transitions for local energy valleys. Those valleys nudge the section boundaries toward measurable audio transitions while maintaining ordered, non-overlapping regions that cover the complete track.

The public API is provider-independent so a learned section detector can replace this heuristic later without changing the UI or EtherControl contract.

VISIBLE SECTION RAIL
--------------------
NOW PLAYING adds direct section targets above the existing timeline:

  [INTRO] [VERSE] [HOOK] [BRIDGE] [OUTRO] [SNAP]

Clicking a named section immediately writes that section's exact start/end range into the existing EtherControl repaint window.

Example:

  HOOK = 31.20 -> 54.80
       -> click HOOK
       -> START = 31.20
       -> END   = 54.80
       -> producer instruction
       -> REPLACE SECTION
       -> ACE repaint
       -> new EtherVersions child

No section action changes version HEAD or the selected A-source lineage.

SNAP MODE
---------
SNAP is optional.

SNAP OFF:
  free-drag the real EtherTimeline waveform and keep the exact region selected.

SNAP ON:
  free-drag the waveform; when released, EtherSections snaps the selection to the nearest detected musical section.

The numeric START/END fields remain available as the precision fallback in either mode.

TIMELINE VISUALIZATION
----------------------
EtherSections draws structural boundary markers over the existing real 128-bin waveform envelope. EtherTimeline still owns waveform rendering, live playhead, drag selection and A/B source safety.

If EtherCompare B is being auditioned, the selected/edit source remains A exactly as in V0.2O.

PERSISTENCE
-----------
Section maps are stored locally beside analyzed audio:

  song.wav
  song.wav.etherdna.json
  song.wav.etherversion.json
  song.wav.ethersections.json

Loading the track later can reuse the saved section map rather than inferring it again.

CURRENT LIMITS
--------------
- V0.1 section naming uses a structural prior + energy-transition heuristic, not a trained semantic structure model yet.
- Section maps currently use one INTRO / VERSE / HOOK / BRIDGE / OUTRO pass; repeated hooks/verses and arbitrary custom labels come later.
- EtherTimeline remains a 128-bin time-energy envelope rather than sample-resolution waveform peaks.
- Playback/seek still uses MCI millisecond positioning; sample-accurate playback comes later with the EtherPlay playback engine.
- Extend remains intentionally blocked until continuation behavior is separately validated.
- ACE does not claim true component locks or isolated drum/melody/chord conditioning through this adapter.
- SEARCH x4 is sequential until provider-native batching or a dedicated fast Draft engine is wired.
- EtherCritic remains DSP-derived; learned semantic/taste heads come later.
- Pleiadian taste adaptation is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public package.
