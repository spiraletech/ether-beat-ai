ETHERBEAT // ALIEN WORKSHOP V0.2J

UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

  home | create | library | now playing | song lab | engine

The V0.2 UI remains the product chassis. V0.2J activates the first real producer-control provider underneath it without redesigning the shell.

NEW IN V0.2J // LIVE ACE CONTROL PROVIDER
-----------------------------------------
EtherControl is no longer architecture-only.
The managed local ACE-Step 1.5 provider now advertises the control jobs it can actually execute and translates EtherBeat control requests into ACE's current source-audio task API.

LIVE TASK MAPPING
-----------------
EtherBeat mode            ACE provider task
------------------------- -----------------
TextToInstrumental        text2music
Variation                 cover
Audio-to-Audio            cover
Replace Section           repaint
Extend                    BLOCKED

Variation / Audio-to-Audio send source audio plus EtherBeat reference strength as ACE audio_cover_strength.
Replace Section sends source audio plus the validated repainting_start / repainting_end temporal window.

The output lineage records the provider task, EtherBeat mode, render intent, seed, reference strength and edit-window values.

STRICT CAPABILITY TRUTH
-----------------------
The managed ACE provider now advertises:
- TextToInstrumental
- Variation
- AudioToAudio
- ReferenceAudio
- ReplaceSection
- DraftRole
- QualityRole
- ControlRole
- LocalRuntime
- TemporalControl

It deliberately does NOT advertise:
- Extend
- ComponentLocks
- DrumConditioning
- MelodyConditioning
- HarmonyConditioning

EtherBeat therefore refuses unsupported precision requests rather than silently dropping musical constraints.

ACE CONTROL CODEC
-----------------
A portable AceStepRequestCodec now owns provider translation.
This keeps provider-specific JSON outside EtherControl and ModelRouter.

The codec validates:
- source audio exists logically for source-conditioned jobs
- repaint windows have valid start/end ordering
- unsupported component locks are rejected
- unsupported isolated drum/melody references are rejected
- unsupported symbolic chord conditioning is rejected
- Extend remains rejected until continuation semantics are separately validated

This means future providers can implement the same EtherControl contract without copying ACE-specific fields into EtherBeat core.

The live Control provider is now available to ModelRouter for source-audio producer jobs. Detailed Variation / Replace Section controls are not exposed as fake buttons in the V0.2J UI yet; the next UI phase can surface only the capabilities the active provider actually supports.

TESTED LIVE-CONTROL CONTRACT
----------------------------
A dedicated ACE control smoke test verifies without downloading model weights:
- provider capability advertisement is truthful
- TextToInstrumental maps to text2music
- Variation maps to cover
- Audio-to-Audio maps to cover
- cover includes source audio, instruction and reference strength
- Replace Section maps to repaint
- repaint includes source audio and exact start/end window
- Extend remains rejected
- component locks remain rejected by ACE
- symbolic chord conditioning remains rejected by ACE
- existing Core/Search/AutoPromote/Control suites continue to pass
- Windows/MSVC and Ubuntu/GCC compile and execute the same request-codec assertions

CI validates the native backend, provider routing, and exact request translation. It does not perform heavyweight model inference on GitHub runners because the managed ACE model/runtime weights are not installed there.

MODEL / LICENSE NOTE
--------------------
JASCO-style control was studied as a possible specialized provider, but EtherBeat does not bundle JASCO model weights in this build. The current live control implementation reuses the managed ACE-Step foundation already inside EtherBeat.

CURRENT LIMITS
--------------
- V0.2J does not yet expose Variation / Replace Section controls in the graphical UI.
- Extend is intentionally blocked until continuation behavior is validated.
- ACE does not advertise true component-lock, isolated drum/melody, or symbolic chord conditioning through this adapter.
- SEARCH x4 is sequential until provider-native batching or a dedicated fast Draft engine is wired.
- EtherCritic remains DSP-derived; learned semantic/taste heads are later.
- Pleiadian/user taste weighting is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public test package.
