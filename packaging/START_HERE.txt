ETHERBEAT // ALIEN WORKSHOP V0.2R

UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

  home | create | library | now playing | song lab | engine

V0.2R evolves the V0.2Q arrangement workspace instead of redesigning the shell. Search, EtherControl, EtherVersions, EtherCompare, EtherTimeline, EtherSections and EtherArrangement remain intact; EtherAssemble turns the persistent arrangement graph into a real new WAV.

NEW IN V0.2R // ETHERASSEMBLE V0.1
----------------------------------
NOW PLAYING adds:

  ASSEMBLE SONG

The action resolves the current EtherArrangement plan slot by slot and writes a physical PCM16 WAV under:

  %LOCALAPPDATA%\EtherTech\EtherBeat\library\assembled\<source>\

SOURCE + DUPLICATE SLOTS
------------------------
Source-backed slots are decoded from the parent song through Windows Media Foundation. EtherAssemble slices the exact stored source start/end range.

Duplicate slots therefore reuse the same measured source audio rather than regenerating it.

PLACEHOLDER SLOTS
-----------------
A +ALT / placeholder slot has no source timestamps. During ASSEMBLE SONG, V0.2R resolves it through the existing Quality provider role using:
- placeholder instruction
- expected section duration inferred from same-kind source sections when available
- current BPM/key
- current producer direction
- full arrangement blueprint

The generated fragment is then decoded and inserted into the arrangement.

IMPORTANT: V0.2R placeholder generation is an independent Quality section render. It is not yet neighboring-waveform-conditioned continuation. The manifest marks placeholder material as generated rather than pretending it came from the parent song.

PCM FORMAT NORMALIZATION
------------------------
EtherAssemble works on normalized interleaved float PCM internally.

The parent track establishes the output format when source-backed slots exist. Generated fragments are converted to match it with:
- channel-layout conversion
- linear sample-rate conversion

This allows, for example, a 44.1 kHz source and a 48 kHz generated fragment to coexist in one final render.

CROSSFADE ASSEMBLY
------------------
V0.2R applies a bounded 20 ms linear crossfade at section joins.

The final render is written as PCM16 RIFF/WAVE. No source file is overwritten.

ASSEMBLY MANIFEST
-----------------
Each assembled WAV receives:

  <audio>.etherassemble.json

Schema:

  etherbeat.assemble.v1

The manifest records:
- parent source audio
- arrangement revision
- output path
- sample rate / channels / duration
- crossfade setting
- slot ID / label / origin
- whether each slot was generated
- each slot input duration
- each slot output start/end timing

POST-RENDER PIPELINE
--------------------
After the WAV is written:

  assembled WAV
      -> native audio analysis
      -> EtherDNA sidecar
      -> EtherVersions.register_child(parent, assembled)
      -> operation = arrangement_assemble
      -> Library refresh
      -> NOW PLAYING

The original song, arrangement plan and all prior versions remain untouched.

CI does not run heavyweight ACE inference because local model/runtime weights are not installed on GitHub runners. Provider request/routing code is compiled and tested; real placeholder inference happens on the user's configured local runtime.

CURRENT LIMITS
--------------
- Placeholder material is independently generated in V0.2R; context-conditioned in-between generation/cross-section continuation comes later.
- Crossfades are fixed at 20 ms in the current UI; the core accepts 0-250 ms.
- Sample-rate conversion is linear V0.1 resampling, not a future high-order production resampler.
- EtherSections still begins from an energy-transition structural heuristic rather than a learned semantic section classifier.
- EtherTimeline remains a 128-bin time-energy envelope rather than sample-resolution waveform peaks.
- Playback/seek still uses MCI millisecond positioning.
- Extend remains intentionally blocked until continuation behavior is separately validated.
- SEARCH x4 is sequential until provider-native batching or a dedicated fast Draft engine is wired.
- EtherCritic remains DSP-derived; learned semantic/taste heads come later.
- Pleiadian taste adaptation is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public package.
