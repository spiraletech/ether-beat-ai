UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

NEW IN V0.2G // ETHERSEARCH V0.1
-------------------------------
CREATE is now connected to the multi-candidate engine stack instead of the old one-shot generation path.

Pressing SEARCH x4 performs:

  source prompt
      -> EtherComposer
      -> EtherDraft x4
      -> Provider Router
      -> four local candidate audio files
      -> native EtherPlay-derived FFT analysis on each candidate
      -> EtherDNA sidecar persistence
      -> EtherCritic ranking
      -> promoted winner
      -> Now Playing

All candidate audio remains in the private local Library. EtherSearch does not delete the alternates after choosing a winner.

ETHERSEARCH CONTRACT
--------------------
EtherSearch V0.1 is renderer-agnostic orchestration above EtherDraft and EtherCritic.

For every candidate it preserves distinct state for:
- generation success/failure
- audio path / seed lineage
- analyzer success/failure
- EtherDNA persistence

A candidate can therefore generate successfully but fail analysis without being mislabeled as a model-generation failure.

If analysis fails, the candidate remains in the batch and diagnostics, but EtherCritic will not invent a score for it.

SEARCH MANIFEST
---------------
Each search writes:

  <draft-batch-id>.ethersearch.json

The search manifest links:
- schema etherbeat.search.v1
- search / draft batch ID
- EtherDraft manifest
- EtherCritic manifest
- candidate count
- analyzed candidate count
- persisted DNA count
- promoted winner candidate index
- winner seed / audio path
- per-candidate generation/analysis/DNA state
- analyzer error notes

The linked files now form a complete local lineage graph:

  .etherdraft.json
      -> candidate WAVs
      -> .etherdna.json sidecars
      -> .ethercritic.json
      -> .ethersearch.json

LIVE CREATE FLOW
----------------
The existing EtherBeat CREATE screen remains the UI anchor.
Its main action now reads SEARCH x4.

The current live behavior is:
- build four Draft-intent candidates
- analyze all successful candidates automatically
- persist EtherDNA
- rank candidates against EtherComposer numeric intent
- promote the highest measured candidate
- open that winner in NOW PLAYING
- leave every alternate in LIBRARY

If no candidate can be measured well enough to produce a Critic winner, EtherSearch reports failure while retaining candidate files/manifests for diagnostics.

TESTED ETHERSEARCH CONTRACT
---------------------------
A dedicated portable search smoke test generates four candidates using the mock Draft provider.
Three receive successful synthetic audio analysis and EtherDNA; one deliberately fails analysis.

The test verifies:
- four draft candidates survive the batch
- three analyzed candidates persist three DNA sidecars
- analyzer failure remains candidate-local
- EtherCritic receives the measured candidates
- candidate 2 is promoted as the expected winner
- failed-analysis candidate remains unscored
- Draft, Critic and Search manifests all persist
- Windows/MSVC and Ubuntu/GCC run the same orchestration assertions

CURRENT LIVE PROVIDER
---------------------
ACE-Step remains the current local text-to-instrumental provider and advertises Draft + Quality capability.
Because no separate fast Draft model is installed yet, SEARCH x4 currently invokes the same local foundation renderer four times sequentially.
This is architecturally correct but can be slower than the future dedicated Draft path.

CURRENT LIMITS
--------------
- EtherSearch V0.1 generates candidates sequentially; provider-native batching/parallel inference comes later.
- The promoted Draft winner is not yet re-rendered through a dedicated final Quality pass.
- EtherCritic V0.1 uses deterministic DSP-derived EtherDNA only.
- Learned CLAP/MERT-style semantic scoring is a later critic head.
- Pleiadian/user taste weighting is not trained yet.
- Dedicated Control and Vocal providers are not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public test package.
