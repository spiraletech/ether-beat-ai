ETHERBEAT // ALIEN WORKSHOP V0.2H

UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

  home | create | library | now playing | song lab | engine

NEW IN V0.2H // ETHERPROMOTE V0.1
--------------------------------
EtherSearch no longer stops at the Critic-selected draft.

The default CREATE pipeline is now:

  source prompt
      -> EtherComposer
      -> EtherDraft x4
      -> Provider Router / Draft role
      -> four local candidate audio files
      -> native EtherPlay-derived FFT analysis
      -> EtherDNA sidecars
      -> EtherCritic ranking
      -> Critic-selected draft winner
      -> EtherPromote
      -> Provider Router / Quality role
      -> final Quality render
      -> final audio analysis + EtherDNA
      -> NOW PLAYING

The original winning draft and all alternates remain preserved. The Quality render is written into a separate promoted/<search-id>/ directory so identical seed naming cannot overwrite the draft that earned promotion.

ETHERPROMOTE CONTRACT
---------------------
V0.1 promotes only a measured Search winner.

Requirements:
- EtherSearch must have a Critic winner
- the winning draft must have a persisted EtherDNA sidecar
- a provider must advertise the Quality role
- the final Quality render must be analyzable
- final EtherDNA must persist successfully

If the winning draft has no DNA, EtherPromote refuses to invent a preservation target.

CURRENT ACE LIMIT
-----------------
The current ACE-Step provider advertises TextToInstrumental + Draft + Quality, but not reference-audio conditioning.

Therefore V0.1 Quality promotion does NOT pretend to preserve the draft waveform directly.
Instead it locks:
- Critic-selected candidate lineage
- winning seed
- original Composer intent
- measured winning EtherDNA target

The measured DNA summary is injected into the Quality request with explicit preservation instructions.
A future Control/reference-capable provider can upgrade this same contract to direct audio-conditioned promotion without replacing the EtherBeat UI or Search architecture.

DNA PRESERVATION CHECK
----------------------
The Quality render is analyzed again after generation.
EtherPromote compares source-winner DNA against final-render DNA across:
- energy
- low-end weight
- rhythmic activity
- brightness
- spectral center

The resulting 0..1 preservation score is stored in the promotion manifest.
This gives EtherBeat a measurable way to detect when a supposed fidelity upgrade drifted away from the musical identity that actually won the search.

PROMOTION MANIFEST
------------------
Each promotion writes:

  <search-id>-quality.etherpromote.json

It records:
- schema etherbeat.promote.v1
- source candidate index / seed / audio path
- source DNA availability
- Quality provider lineage
- Quality generation state
- Quality analysis state
- Quality DNA persistence
- final Quality audio / metadata paths
- DNA preservation score
- explicit error state

ETHERSEARCH V0.1 + PROMOTION
----------------------------
EtherSearch now preserves two winner concepts:

  draft_winner_*
      = the candidate EtherCritic actually selected

  winner_*
      = the final artifact exposed to the UI

With default settings, winner_* becomes the promoted Quality render when EtherPromote succeeds.
If Quality promotion fails, the measured draft winner remains available and all promotion diagnostics persist instead of deleting the successful Search result.

The search manifest now also links:
- draft winner candidate / seed / path
- quality_promoted state
- promotion manifest path
- Quality DNA preservation score
- promotion error
- final winner path / seed

CURRENT LIMITS
--------------
- ACE-Step is still both the live Draft and Quality provider, so V0.2H uses the same foundation renderer for both roles.
- SEARCH x4 is sequential until provider-native batching / a dedicated fast Draft engine is wired.
- ACE does not yet advertise direct reference-audio conditioning in EtherBeat; true waveform-locked promotion awaits a Control-capable provider.
- EtherCritic remains DSP-derived; learned CLAP/MERT-style semantic heads are later.
- Pleiadian/user taste weighting is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public test package.
