ETHERBEAT // ALIEN WORKSHOP V0.2L

UI ANCHOR
---------
EtherBeat keeps the EtherPlay-derived navigation spine intact:

  home | create | library | now playing | song lab | engine

V0.2L is an engine-structure release. It adds persistent music version lineage underneath the existing V0.2K producer workspace rather than redesigning the shell.

NEW IN V0.2L // ETHERVERSIONS V0.1
----------------------------------
EtherBeat now treats generated edits as a version graph instead of unrelated files.

Each tracked audio node receives:

  <track>.etherversion.json

The sidecar stores:
- schema version
- version id
- root id
- parent version id
- current audio path
- parent audio path
- operation type
- producer instruction
- creation timestamp

ROOT / CHILD MODEL
------------------
On the first control edit of a track:

  ORIGINAL
     -> registered as ROOT

The successful control render becomes a child:

  ORIGINAL
     -> VARIATION A

Editing that child continues the graph:

  ORIGINAL
     -> VARIATION A
          -> REPAINT A1

All nodes in the chain preserve the same root id.

AUTOMATIC ROUTER INTEGRATION
----------------------------
Version registration lives at ModelRouter level, not only inside Win32 button code.

Any successful source-conditioned EtherControl render with reference audio automatically registers:
- the source as a root/version node when needed
- the output as a child node
- operation lineage (variation, audio-to-audio, replace-section, etc.)
- the producer instruction used for the edit

This makes lineage available to future UI, CLI and API callers without duplicating persistence logic.

HEAD / PROMOTION
----------------
EtherVersions includes per-root HEAD state under the local library metadata area.

A version can be promoted without deleting siblings or ancestors.
The engine can resolve the currently promoted audio from any node in the same lineage.
Moving HEAD to the parent provides rollback semantics while preserving every file.

The V0.2L core API includes:
- ensure_root(audio)
- register_child(parent, child, operation, instruction)
- lineage_for_audio(audio)
- parent_audio_for(audio)
- promote(audio)
- promoted_audio_for(audio)

LINEAGE QUERY
-------------
For the currently selected node, EtherVersions can resolve:
- parent
- direct children
- root identity
- promoted version id
- whether the current node is HEAD

This is the substrate for the next visible Sessions-style controls: PARENT, PROMOTE, HEAD and branch/version browsing in Now Playing.

CURRENT PRODUCER FLOW
---------------------
CREATE:
  EtherComposer
      -> EtherSearch x4
      -> EtherDNA
      -> EtherCritic
      -> EtherPromote
      -> NOW PLAYING

CONTROL:
  NOW PLAYING
      -> Variation / Replace Section
      -> ModelRouter
      -> ACE cover / repaint
      -> new local audio
      -> EtherVersions automatic child registration
      -> NOW PLAYING

ORIGINAL PRESERVATION
---------------------
Control operations still never overwrite the source audio.
EtherVersions adds graph metadata on top of the existing local-file preservation model.

CURRENT LIMITS
--------------
- V0.2L adds the persistent version engine; dedicated PARENT/PROMOTE/branch buttons are the next UI layer.
- Extend remains intentionally blocked until continuation behavior is separately validated.
- ACE does not claim true component locks or isolated drum/melody/chord conditioning through this adapter.
- SEARCH x4 is sequential until provider-native batching or a dedicated fast Draft engine is wired.
- EtherCritic is still DSP-derived; learned semantic/taste heads come later.
- Pleiadian taste adaptation is not trained yet.
- Dedicated Vocal provider is not wired yet.
- No private corpus, vocals, LoRAs, checkpoints or training data ship in this public package.
